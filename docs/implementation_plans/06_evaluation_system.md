# Evaluation System (CodeWikiBench) Implementation Plan

## Overview
Implement the **CodeWikiBench** evaluation framework, specifically the "Judge Agent" system and hierarchical score aggregation, to replace the current heuristic-based metrics.

## Current State
- `EvaluationMetricsSystem.cs` uses simple heuristics (word count, regex).
- `RubricGenerationService.cs` exists and generates rubrics.

## Gaps to Address
- **Lack of Semantic Evaluation:** Current system checks if code blocks exist, not if they are correct or helpful.
- **Missing Judge Agents:** The concept of an LLM acting as a judge for specific rubric items is missing.
- **Hierarchical Aggregation:** Score aggregation needs to follow the weighted tree structure of the rubric.

## Implementation Steps

### 1. Implement Judge Agent
- Create `JudgeAgent` class.
- **Input:** `WikiPage` content + Specific `RubricRequirement` (leaf node).
- **Task:** LLM prompt: "Does this documentation satisfy requirement X? Rate 0-1 and explain."
- **Output:** Score (0/1 or 1-5 scale), Reasoning.

### 2. Evaluation Orchestrator
- Iterate through the `EvaluationRubric` (generated by `RubricGenerationService`).
- For each Leaf Node, dispatch a `JudgeAgent`.
- Collect scores.

### 3. Hierarchical Score Aggregation
- Implement the "Bottom-Up Weighted Aggregation" algorithm from the paper.
    - Node Score = Sum(ChildScore * ChildWeight) / Sum(ChildWeights).
    - Calculate Reliability (Standard Deviation) if multiple judges are used.

### 4. Replace/Augment Existing Metrics
- Deprecate heuristic methods in `EvaluationMetricsSystem` or keep them as "Static Checks".
- Main quality score should come from the LLM Judge.

## Required Changes
- **Files:** `codeMRI.Core/Services/EvaluationMetricsSystem.cs`, `codeMRI.Agents/Agents/ValidatorAgent.cs` (could act as Judge).
- **New Classes:** `JudgeAssessment`, `ScoreAggregator`.

## Expected Outcomes
- Semantic assessment of documentation quality.
- Scores reflect actual utility (completeness, accuracy) rather than just length.
