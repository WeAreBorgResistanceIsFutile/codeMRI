# Evaluation System (CodeWikiBench) Implementation Plan

## Overview
Implement the **CodeWikiBench** evaluation framework, specifically the "Judge Agent" system and hierarchical score aggregation, to replace the current heuristic-based metrics.

## Current State
- `EvaluationMetricsSystem.cs` uses simple heuristics (word count, regex).
- `RubricGenerationService.cs` exists and generates rubrics.

## Gaps to Address (Based on CodeWiki Paper Analysis)
- **Complete CodeWikiBench Missing:** Current system lacks the comprehensive evaluation framework described in Section 4
- **Rubric Generator Agent Missing:** Missing the agent that generates hierarchical rubrics from official documentation
- **Multi-Model Consensus Missing:** No implementation of evaluation using different model families to reduce bias
- **Hierarchical Score Aggregation Limited:** Missing standard deviation tracking and reliability quantification
- **Benchmark Integration Missing:** No connection to CodeWiki repository benchmark set

## Implementation Steps

### 1. Implement Complete CodeWikiBench Framework
- **Rubric Generator Agent:** Create agent that processes official documentation into hierarchical JSON rubrics
- **Multi-Model Judge System:** Implement 3+ independent Judge Agents using different model families
- **Binary Leaf Assessment:** Judges evaluate only leaf-level requirements with binary adequacy decisions
- **Reasoning Collection:** Each judgment includes concise reasoning as per CodeWiki methodology

### 2. Evaluation Orchestrator
- Iterate through the `EvaluationRubric` (generated by `RubricGenerationService`).
- For each Leaf Node, dispatch a `JudgeAgent`.
- Collect scores.

### 3. Implement Hierarchical Score Aggregation with Reliability
- **Weighted Aggregation:** Implement the exact formula from CodeWiki Section 4.3
- **Reliability Quantification:** Track standard deviation σ for each node
- **Uncertainty Propagation:** Ensure uncertainty propagates appropriately through hierarchy
- **Dual-Metric Approach:** Provide quality assessment with confidence bounds

### 4. Integrate with CodeWiki Repository Benchmark
- **Benchmark Repository Set:** Test against the 21 open-source repositories used in CodeWiki evaluation
- **Performance Comparison:** Automatically compare against DeepWiki baseline scores
- **Language-Specific Analysis:** Generate evaluation reports by programming language category
- **Scalability Validation:** Test across repository sizes from 16K to 1.7M LOC

## Required Changes
- **Files:** `codeMRI.Core/Services/EvaluationMetricsSystem.cs`, `codeMRI.Agents/Agents/ValidatorAgent.cs` (could act as Judge).
- **New Classes:** `JudgeAssessment`, `ScoreAggregator`.

## Expected Outcomes (CodeWiki Compliance)
- Full CodeWikiBench compliance with hierarchical rubrics and agentic assessment
- Multi-model consensus evaluation reducing single-model bias
- Reliability scores with standard deviation tracking
- Direct comparison against DeepWiki baseline (aim for ≥68% quality score)
- Support for the original CodeWiki repository benchmark set
